## Organisation de la documentation

La navigation suit l'ordre de construction du système — des décisions vers les assemblages.

| Niveau | Contenu | Règle d'appartenance |
|---|---|---|
| **Foundations** | Couleur, typographie, espacement, rayons, largeurs, conteneurs, effets, motion | Les décisions de design. Aucun composant, uniquement des tokens. |
| **Primitives** | `Icon`, `ModuleIcon`, `Logo`, `Avatar`, `Badge`, `Scrollbar` | Rend un seul élément. Aucune composition, aucun état interne. |

| **Subcomponents** | `ButtonGroupItem`, `DropdownItem`, `DropdownSelectItem`, `DropdownDivider` | N'a de sens qu'à l'intérieur d'un parent. Ne s'utilise jamais seul. |
| **Components** | Tout le reste | Porte des variantes, des états ou de l'interaction, et compose éventuellement les niveaux inférieurs. |

L'ordre du volet latéral est figé dans `.storybook/preview.ts` (`options.storySort`). Les entrées
non listées se rangent après leurs voisines déclarées ; l'ordre des stories *à l'intérieur* d'un
fichier reste celui du code, jamais alphabétique.

## Icônes

Le jeu d'icônes est [Lucide](https://lucide.dev) (ISC) — **189 icônes**, exactement le sous-ensemble
publié dans la frame Figma `Icons/Lucide`, pas la bibliothèque entière.

Les fichiers sont **générés**, jamais écrits à la main :

```bash
# 1. ajouter/retirer un nom Lucide dans scripts/icons.manifest.txt
# 2. régénérer
npm run icons
```

Quatre tailles : `16 | 20 | 24 | 32`. Les icônes sont dessinées sur une grille de 24px en
`stroke-width: 2` et le stroke suit la boîte — le stroke effectif vaut donc `2 × taille / 24`
(1,33 / 1,67 / 2,00 / 2,67). Il n'est pas compensé aux petites tailles. Les glyphes *à l'intérieur*
d'un contrôle (coche de `Checkbox`, fermeture de `Tag`) sont des ornements et échappent au plancher
de 16px.

## Artwork des modules

`ModuleIcon` porte les deux niveaux publiés dans Figma, sur le modèle des tokens :
`variant="illustration"` est la **primitive** (le dessin seul), `variant="logo"` la **sémantique**
(le même dessin sur sa tuile) — et c'est la valeur par défaut.

Comme les icônes, les fichiers sont générés depuis les exports Figma bruts :

```bash
npm run module-art
```

11 modules. `Eudr` est absent de `ModuleName` : la variante est vide dans Figma et son artwork se
trouve en réalité sur `Trace` — voir ADR-0005.

## Architecture des tokens

Les tokens sont organisés en deux niveaux :

**Primitives** — les valeurs brutes de la palette (couleurs, typographie, espacement, effets). Ne sont jamais utilisées directement dans les composants.

**Sémantiques** — les usages nommés (`bg-brand-solid`, `fg-secondary`, `border-error`…) qui référencent les primitives. Ce sont ces tokens que les composants consomment.

Tous les tokens sont préfixés `--ds-` et exposés comme variables CSS sur `:root`.

Après toute modification des sources de tokens :

```bash
npm run tokens
```

## Contribuer

Le dépôt est ouvert aux contributions internes. Pour ajouter un composant :

1. Créer le dossier `components/NomComposant/`
2. Ajouter `NomComposant.vue`, `NomComposant.stories.ts`, et `NomComposant.mdx`
3. Exporter depuis `components/index.ts`
4. Ouvrir une PR sur [GitHub](https://github.com/Abi-shai/tolbi-design-system)

Un composant est **stable** quand sa page MDX est présente et sa description dédupliquée.
